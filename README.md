# chapter-review-builder

将指定章节的教材/课件转化为可直接打印的 Word (`.docx`) 复习资料包。引擎自动完成排版、公式重建与质量校验。

## 📦 交付结构

单章成品严格控制在 **8–15 页**（超页数触发强制拆册），排版顺序固定：

*   **页眉**：科目、教材版本、原书页码。
*   **核心考点**：本章解决的问题及考试落点。
*   **知识脉络**：层级缩进的拓扑树（主干包含公式）。
*   **正文拆解**：按节展开（讲解 + 降维注释 + 国内考法 + 例题）。**强制要求：每个知识点配一道题**，题/提示/答案分行排版。
*   **附录与收尾**：易错点备忘录、课后习题题库、末页一页纸速查卡。

## 🧮 公式渲染

输出为 **Word 原生 OMML 公式**（非截图），支持字号缩放与双击编辑。

*   **转换链路**：Markdown (LaTeX) → MathML → Office 原生 `MML2OMML.XSL`。
*   **分式优化**：修复 `latex2mathml` 默认输出的斜杠分式，引擎在出口统一转为上下堆叠结构，避免在 Word 中形似乱码。

## 📝 构建流与自动化校验

Markdown 是唯一可迭代资产，docx 随源码随时重出。针对长文档极易出现的编号与排版错误，设立两道防线：

1.  **前置拦截 (`lint`)**：编译前检查私有语法、行内矩阵、树块内公式等禁用写法。
2.  **后置审计 (`audit`)**：编译后统计公式转换失败数、私有区字符、交叉引用悬空（如指向不存在的公式号）。
3.  **视觉验收**：脚本无法识别公式挤压、上下标重叠等视觉灾难。需渲染为 PDF/PNG 后，由人工完成关键页抽检。

## ⚙️ 安装

1.  前往 **Releases** 页面下载 `chapter-review-builder.zip`（不要用 GitHub 自动生成的 `Source code`）。
2.  解压得到 `chapter-review-builder` 文件夹，放入宿主的 skills 目录。
3.  **注意**：确保 `SKILL.md` 位于该文件夹根目录，且文件夹名称与 `SKILL.md` 内部的 `name` 字段完全一致。

## 💻 环境要求

*   **系统**：Windows
*   **软件**：Microsoft Office（**暂不支持 WPS，后续视底层兼容情况决定是否适配**）
*   **技术依赖**：页数与 PDF 导出依赖 Word COM 接口；公式转换依赖 Office 原生 `MML2OMML.XSL`。
*   **WPS 避坑**：当前版本下，WPS 接管 `Word.Application` 会导致兼容层静默失败（无报错但无法导出），请务必使用原生 Office。
*   **Python 依赖**：`python-docx`、`latex2mathml`、`lxml`、`pymupdf`。

## ⚠️ 已知限制

*   **版式单一**：目前仅内置一套排版引擎（七种容器 + 自动分页），暂不支持自定义期刊风或纯笔记风。
*   **单章处理**：一次仅处理一章，需人工指定页码范围。
*   **PDF 陷阱**：教材 PDF 的文字层不可信（OCR 常将数学符号识别错，如 `λ` 变 `入`）。公式需一律回原书按页面图人工或视觉模型重建。
*   **COM 进程驻留**：Word COM 偶发静默卡死，脚本自带超时强杀机制（清理残留 `WINWORD` 进程），但极少数情况下仍需人工等待超时。

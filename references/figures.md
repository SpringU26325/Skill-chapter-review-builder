# 图片通道

只在贴示意图时读。表格与公式不走这里，各有一条更合适的通道。

## 一、先分清楚：什么该做成图

| 内容 | 做法 | 理由 |
|---|---|---|
| 流程图符号、结构框图、受力图、波形图、几何示意 | **裁图** | 形状本身携带信息，文字描述既不准也难记 |
| 表格 | **md 文字表格** | 可编辑、可搜索、放大不糊；整表截图会连字一起糊掉 |
| 公式 | **LaTeX 重建** | 有原生 OMML，行内行间都对齐；截图公式无法参与排版 |
| 代码、伪代码 | `:::code` | 等宽块，本就清晰 |

判据只有一句：**这张东西离开图就没法表达吗**。是，才裁图。

「图标」不是这条通道的对象。齿轮、放大镜那类 16px 装饰符号不进复习资料——它们不承载内容，只会制造视觉噪音。

## 二、裁图：`scripts/复习资料_裁图.py`

两个动作，一个管定位、一个管落地。

### 1. 定位（probe）

```
"<py>" 复习资料_裁图.py probe <主干.pdf> --page 90 --grid 50
```

输出一张**带坐标网格的整页图**到 TEMP，边缘标 pt 数值。扫描版主干整页就是一张位图，没有矢量对象，子区域的框算不出来，只能按网格目视读。读完后按读数写 `--box`。

`--page` 用**物理页**（1 基，即台账里的页码），内部按 `page-1` 取页。

### 2. 裁切（crop）

```
"<py>" 复习资料_裁图.py crop <主干.pdf> --page 90 --box 336,452,518,552 \
      --subject 大学物理 --file 第3章_例3.12_球在纸上 --printed 74 \
      --note "例 3.12 用图：球在纸上、手拉纸、x-y 坐标系"
```

- 落盘到 `复习资料\_生产\_源稿\figures\<科目>\<file>.png`，固定 300dpi、无 alpha。
- 同时写 `figures\_图索引.md`：主干文件、物理页、印刷页、裁切框、内容、日期。**同名重裁替换原行**，不是追加。
- 默认拒绝覆盖已有同名图，确认要覆盖加 `--force`。

**裁几轮是正常的。** 第一刀几乎总会带进正文或切掉箭头，看一次、调一次、再看一次。判据是四个方向都有余量，且没有正文、图注、相邻图混进来。

### 3. 分辨率：别自己骗自己

脚本会算主干整页的有效 dpi（原图像素宽 ÷ 页面宽 × 72），低于 200 直接 WARN。

- 清晰度上限等于主干自身的扫描分辨率：以 174 dpi 的扫描件为例，`--dpi 300` 只是插值放大，不会多出细节。换一套主干按实际分辨率算（原图像素宽 ÷ 页面英寸）。
- 因此**图的质量上限等于主干扫描分辨率**，换 `--dpi` 没有意义。要更清只能换更清的源。
- 174 dpi 的 6cm 插图在屏幕与普通打印上可用，但不该和原生 300dpi 的矢量图比。

### 4. 只裁图形，不裁图注

图注由 md 写、由引擎排。把「图 3.18 例 3.12 用图」一起裁进来，等于把文字压成像素：不能搜、缩放会虚、字号也跟着走。

同理，不要为了省事把「符号 + 一段说明」整块裁下来——说明写进正文，图只留图形。

## 三、md 怎么写

独占一行：

```
![图 3.18　例 3.12 用图](figures/大学物理/第3章_例3.12_球在纸上.png)
```

- 路径按 **md 所在目录**解析。源稿平铺在 `_源稿\`，所以前缀就是 `figures/<科目>/`。
- 文件名不要带括号——正则到第一个 `)` 就截断。
- `{w=6.4}` 可写可不写，单位 cm，上限 16.6（版心宽）。

**宽度规则**：不写时按「像素 ÷ 300dpi × 2.54」还原，夹在 3–16.6cm。裁图固定 300dpi 出图，所以这个换算正好等于这张图在教材上原本多大——比手写一个 cm 数可靠。只有外部截图（来源不是裁图脚本）才需要手写 `{w=}`。

**图注**必须写，原样输出，8pt、`MUTED=5F6B78`、居中、紧贴图下。编号手写（`图 3.18`），引擎不自动编号：正文里已有「如图 3.18 所示」这类引用，自动编号会和它脱钩。

## 四、引擎怎么排

`复习资料_build.py` 在三个位置认图片行：正文顶层、`:::box` 一类容器内、`:::quiz` 题卡内。

- 图单独成段、居中，`space_before=6pt`、`space_after=2pt`。
- 段落设 `keep_with_next` 与 `keep_together`：图与图注不能被分页拆开。
- 图注段 `space_before=2pt`、`space_after=9pt`（题卡内收到 3pt）。

**一处必须知道的实现约束**：图片分支要放在 `render()` 主循环 `else: buf.append(s)` 之前。连续非空行会被 `flush()` 用空格拼成一个段落，图片行落进 `buf` 就变成一行字面上的 `![…](…)`。

## 五、质检

`复习资料_lint_md.py`（md 阶段）：

| 级别 | 条件 |
|---|---|
| ERROR | 图片文件不存在 |
| ERROR | 图注为空 |
| ERROR | 扩展名不是 png/jpg |
| ERROR | `{w=}` 超版心，或不写宽度但折算后超版心 |
| WARN | 未登记在 `_图索引.md` |
| WARN | 同一张图重复引用 |

`复习资料_audit.py`（docx 阶段）改了三项判据——**这一条与旧版不同，务必看完**：

| 指标 | 旧判据 | 新判据 |
|---|---|---|
| `w:drawing` | 应为 **0** | 应**等于** md 图片引用数 |
| `word/media/` | 应为 0 | ≤ 引用数（同图复用会去重） |
| `w:pict` / `w:object` | 应为 0 | 仍须为 0 |

旧判据的前提是「成品里一张图都没有」，用来证明公式不是截图。引入图片通道后它必然失败，所以改成对账式：**md 引用几张，docx 里就该有几个 drawing**。公式仍然必须全是 OMML，这条没变。

交付前用眼睛确认三件事：图不糊、图与图注不跨页、图没被版心裁掉。

## 六、常见错误

| 现象 | 原因 |
|---|---|
| 正文里出现一行 `![…](…)` 原文 | 图片行落在连续段落中间，被 `flush()` 拼进了正文 |
| 图很大、撑满版心 | 来源不是裁图脚本（无 300dpi 约定），要手写 `{w=}` |
| 图与图注分在两页 | 段落属性被后续版本改掉了，检查 `keep_with_next` |
| audit 报 drawing 数与引用数不等 | 有图路径写错，构建时进了 `IMG_FAIL`；看构建输出的「图片失败清单」 |
| 图注文字是从教材裁进来的 | 裁切框画到了图注上，重裁 |

## 七、主干换版怎么办

`_图索引.md` 就是为这件事存在的。按「物理页」回查原图，重裁同名覆盖（不用 `--force` 以外的手续，索引行会自动替换）。主干换版后页码会漂，所以**印刷页一列必填**——它比物理页稳定。换版时改 `_配置.md` 的主干行（文件 + 页码换算），台账只追加一条事实。

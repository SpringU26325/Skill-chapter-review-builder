# 交付、命名与多会话协作（Step 3 读这一份）

> **什么时候读**：docx 构建完成、要交付、要定命名或安排多会话的时候。动 Word 导出、页检、并发锁的细节在 `render.md`。

## 一、存放与命名

- **分层存放（强制）**：科目根层 `复习资料\<科目>\` 放原件（真题、笔记、课件），成品一律进 `复习资料\<科目>\_成品\`。**禁止散落在 `复习资料\` 根目录**，也**不要**把 docx 与原件平铺在科目根层。发现历史文件散落时主动迁移。
- 文件名严格为：`[科目名称]_第X章[上|下|中|拓展]_复习资料.docx`（方括号后缀可省）。
- 源稿放 `复习资料\_生产\_源稿\`，命名 `<科目>_第X章.md`（**必须带科目前缀**）。不要用 `math`、`ch1`、`gs6a` 这类泛名——多科目并行会互相覆盖。

**文件名即接口**：`<科目>_第X章.md` → `复习资料\<科目>\_成品\<同名>_复习资料.docx`。页眉写在 md 的 `@header`，符号表 `<科目>_notation.md` 存在就自动注入。没有清单文件、没有每章脚本。

## 二、交付话术

- 单册：**「XX第X章已完成并导出到 复习资料\XX\_成品\XX_第X章_复习资料.docx，自检报告无异常，请查收。」**
- **一章多册时列出全部文件名**（如「上 / 下 / 拓展 共 3 份，各 8–12 页」），不要只报第一册。
- 可加一句用法提示：文档内可点击（首页「速达」、脉络行、小节下的「对应题目」），Word 左侧导航窗格可展开层级、标题可折叠。不要把这条写成验收结论。
- **不要用文件预览面板打开 docx**：本机预览字号太小、不可读，且预览进程会锁住 docx 导致构建失败。交付时只给路径。

## 三、收尾清理

`复习资料\<科目>\_成品\` 是成果仓库，`_生产\` 下的 `_render\` / `_迁移\` 是工作台，交付即清。

**可直接删**：渲染图 `*.png`、带版本后缀的过程 PDF（`v2…v9`、`fix1…fix7`、`preview*`）、引用的路径已不存在的脚本、一次性探测脚本（`t*.py`、`probe*.py`、`test_*.py`）、0 字节文件、空目录、构建中间 docx。

**必须保留**：`复习资料\_生产\_源稿\` 下的各章 `.md`、`<科目>_notation.md`、`复习资料\_生产\_locks\`（删了并发保护失效）、`复习资料\<科目>\_成品\` 下的成品。

**删除前**：`grep -l <文件名> scripts\*.py` 确认无引用；只删过程目录，**不碰** `复习资料\<科目>\_成品\` 成品、科目根层的原件、素材库（含工作区外的主干）、工作区台账与 `_配置.md`。

**原因**：同一份稿子会迭代出十几版，攒到几百个文件后「哪个是最终版」不可判断，`grep`/`glob` 的结果被历史文件淹没。清理的价值是**让目录本身说明当前进度**。

## 四、多科目 / 多会话并发

**可以同时开工**，三条前提：

1. **文件带科目前缀**——重建脚本靠前缀认科目。
2. **只改自己的文件**；工作区台账（`复习资料\_生产\_台账.md`）是共享的，改前先读最新版，**只追加本章事实、不整段重写**，别两个会话同时编辑。主干与所有原件（含素材库、工作区外的）**只读**；`_配置.md` 的主干行只在用户指定后改，不自行更换。
3. **构建统一走重建脚本**——按科目分锁（`_生产\_locks\.build_<科目>.lock`），不同科目同时构建互不等待，同科目才排队；默认增量，各科只重建自己改过的章节。

**唯一串行的是 Word COM 转 PDF**（`_生产\_locks\.pdf.lock`，跨科目排队）：Word 是单实例资源，同时转会互相关掉文档。`--pdf` 已包在锁内；手工转前先确认另一个会话没在转。锁与 COM 的全部细节见 `render.md` 第三章。

> 迁移或换机时注意：锁目录变了，新旧锁互不互斥。迁移窗口内禁止任何构建。

## 五、Word COM 纪律

**这一节已整体迁到 `references/render.md`** 第五至七节：手工调用的成套动作、「文档恢复」残留的成因、允许强杀的两处例外、页检脚本优先、导出三条前提、失败判读。

留在这一层的只有一条：**不要在别处复制这套规则**。两处并存必然漂移，上一次就是这么埋下「中文路径不能导出」的误判。

## 六、新科目接入（3 步，不改引擎）

1. 写 `复习资料\_生产\_源稿\<科目>_第1章.md`，头部三行：`# 第1章 …` / `@sub …` / `@header <科目> · 第1章 …`
2. （可选）建 `复习资料\_生产\_源稿\<科目>_notation.md`，内含 `<!-- inject:compact -->…<!-- /inject:compact -->` 段
3. （可选）复制 `scripts\lint\线性代数_lint.py` 为 `<科目>_lint.py` 改规则

成品自动出现在 `复习资料\<科目>\_成品\`，配色、容器、公式处理全部继承。

**别为了「看起来完整」去建用不上的符号表或检查器。** 只有当真存在「一眼看不出错、但读者会误解」的记号约定时（像线代的圆括号=列向量），才值得再写一份 `<科目>_lint.py`。

## 七、交付后同步台账（只写一处）

每章交付后**只更新 `复习资料\_生产\_台账.md`** 一处：页码对照、分册数、成品页数、下一章。主干（文件名、位置、类型、编号单位、页码换算）记在 `_配置.md`，**不在台账重复**；主干有变时改配置那一行，并在台账追加一条事实。

进度只有一处——`复习资料\_生产\_台账.md`。

# 引擎内部机制（只在改 `scripts\` 下的引擎时读）

> **什么时候读**：要改编排版引擎的时候。**日常写复习资料不需要读这一份。**
> 只写 md 时必须守住的几条，见 `md-dialect.md` 第 7 节。

## 〇、模块地图（动之前先定位）

引擎由四个文件组成，改动时先确认落在哪个文件：

| 文件 | 管什么 | 典型改动 |
|---|---|---|
| `scripts\复习资料_build.py` | 入口与组装：命令行参数、并发锁、`Builder`、收尾保存与占用降级 | 版式、分页、块解析、索引与跳转 |
| `scripts\crb_omml.py` | LaTeX → MathML → OMML，以及全部 OMML 后处理 | 公式字形、空槽、算子名、希腊粗体 |
| `scripts\crb_docxkit.py` | python-docx 原语：底纹与边框、run 样式、大纲级别、书签、链接、单元格、图片宽度 | 配色落地、链接生成、表格样式 |
| `scripts\crb_style.py` | 颜色与字体常量（三处共用，改一处全生效） | 换配色、换字体 |

`Builder` 的 35 个方法按下表三组定位，找代码时先看方法名在哪组：

| 组 | 方法 | 用途 |
|---|---|---|
| 索引与跳转 | `index_anchors` `_index_item` `_next_hdr` `_nums` `_match` `_resolve` `_root_anchor` `_tree_link` `_try_anchor` `nav_line` `_back_target` `link_line` | 书签、题目挂靠、脉络与回跳 |
| 页面与样式 | `__init__` `_page` `_styles` `header_footer` | 页面设置、页眉页脚 |
| 块渲染 | `h1` `h2` `h3` `sub` `para` `math` `_pic` `img` `bullet` `container` `_render_code` `_render_tree` `_render_quiz` `_render_blocks` `md_table` | 每种块一个方法，容器内再分派 |

**公式后处理的顺序在 `build.py` 的 `add_math()` 里**，`crb_omml.py` 只提供函数、不决定顺序。改顺序等于改全部成品的字形，先按第五节做全量验证。

## 一、引擎已自动处理（写内容时不用管，但别绕过）

| 坑 | 引擎的处理 |
|---|---|
| 矩阵定界符丢失（`A=[` 被合成一个 run，括号只有一行高） | `tex2omml` 自建 `m:d` + `m:m`：按 `\\` 分行、`&` 分列，单元格递归转 OMML |
| `\|` 吞内容（`‖v-w‖²` 变成 `‖²`） | `_prep()` 全局替换 `\|` → `\Vert` |
| `\qquad` / `\quad` 失效（`<mspace>` 被 XSL 丢弃） | token 层切分，插 `m:r/m:t`，内容用 EM SPACE（U+2003）+ `xml:space="preserve"` |
| 粗体里嵌公式（`**零向量 $\mathbf{0}$**` 漏出源码） | `**...**` 解析后**递归**再解析内部 `$...$` |
| 标题里嵌公式（`### 给定 $\mathbf{b}$` 漏出源码） | `h1/h2/h3` 与容器标题一律走 `add_inline()`，不直接 `add_run(text)` |
| 公式没指定数学字体（继承等线 → 字形回退、像教材截图） | `polish_math()`：遍历所有 `m:r` 插 `w:rFonts ascii/hAnsi/cs="Cambria Math"`；`m:nor` 的中文正体改回等线 |
| Unicode 数学字母（`𝐚` U+1D41A、`𝑥` U+1D465） | `polish_math()` 做 NFKC 归一化还原 ASCII，按码位区间补 `m:sty`（b / i / bi） |
| 相邻矩阵贴死（`[A B]=[I 0][…]` 括号叠一起） | token 循环记 `prev`：相邻矩阵插 1em（`\u2003`），矩阵后接字母插 thin space（`\u2009`） |
| 代码块行距过大（纯文本流程块被拉散） | 纯代码块行距固定 **1.0**；结构块（树）用 **1.14** 并加左缩进 |
| 斜杠除法变成一条长斜杠，压着前面的上下标（`mv_\theta^{2}/l` 排成 `mv²/l`） | 折分式发生在 MML2OMML.XSL，不在 `_force_bar()`：只有 `mrow` **恰好三个子元素**、且这一处除法独占整条公式时才转成 `m:f type=lin`（`5/3` 单独成式会折），`_force_bar()` 再把非单位的 `lin` 提成 `bar` 上下堆叠。同一条 mrow 里再有一项就超界——带等号的公式必然超界，`\gamma=5/3`、`T/T_0=1`、`mv_\theta^{2}/l`、`p=\nu RT/V`、`\mathrm{d}s/\mathrm{d}t` 实测全是普通字符斜杠，`_force_bar()` 遍历不到 `m:f`，够不着。**单位例外**：分子分母的 run 全是正体（`m:sty=p`）时判为单位、保留 `lin`（`m/s` 不排成 m 压在 s 上）；但超过三项的单位（`\mathrm{kg\cdot m/s^{2}}`）同样退化成字符斜杠，所以同一册里单位的斜杠有两种字形（lin 的分数字形 / 普通斜杠），不必追平。作者侧的对策是不赌它折：**除单位外一律写 `\frac`**（连 `5/3`、`T/T_0` 也写），规则见 `md-dialect.md` 第 3 节「除法只有一个写法」 |
| 结构块里公式比周围文字大一圈（OMML 默认继承 10.5pt） | `_shrink_omml()` 把该段 `m:r` 的 `w:sz/szCs` 压到行字号；`polish_math()` 重建 run 时**带上传入的 sz**，否则字号被打回默认 |
| `\dot r`、`\ddot r`、`\vec r`、`\tilde r` 的点/箭头飘到字母上方老远 | MML2OMML 把 `<mover>` 转成 `m:limUpp`（上方极限位）而不是 `m:acc`。`add_math()` 里 `_fix_accents()` 把它改回 `m:acc`，`m:chr` 用组合字符（U+0307 / U+0308 / U+0303 / U+20D7），不是间距字符 U+02D9。`\hat`、`\bar`、`\overline` 本来就是 `m:acc`，不受影响 |
| 叠加重音（`\dot{\hat r}`）的点飘在帽顶上，中间空一大块 | Word 给每个重音都留一个完整重音槽，叠两层就空出 ≈1 pt；而它自己排 `\hat{\dot r}`（窄的在内、宽的外层）是贴的——帽的两臂正好把点围住。`_fix_accents()` 因此把窄重音（`\dot`、`\ddot`）换到里层，输出与 `\hat{\dot r}` 同形。**总高度不变**（Word 的重音槽是固定的），只是把空隙挪到帽外、让点贴着字母。9 pt 正文实测：改前点离帽 16 px@1200dpi，改后点离帽 9 px、帽压在点上 |
| `\lim_{\Delta t\to0}` 的 lim 是斜体、极限挤在右下角 | latex2mathml 输出 `<msub><mo>lim</mo>…</msub>`，MML2OMML 转成 `m:sSub`，底下的 run 没有任何样式——Word 对普通字母 run 默认按变量排，lim 就成了斜体；`m:sSub` 又是「右侧下标」，极限落在右下而不是正下方。`add_math()` 的 `_fix_operators()` 给算子名（lim/sin/cos/log/ln/max/min/det…）补 `m:sty=p` 排正体，极限类（lim/max/min/sup/inf/det…）再把 `m:sSub` 改造成 `m:limLow` 压到正下方。作者照写 `\lim_{…}` 即可，不用 `\limits`、也不用包 `\mathrm`。11-18 定：极限一律放下方，行高不是问题（有极限的地方一般也有分式）。**算子名可能落在 run 中间**（`=detA`、`detA+detB`），只按开头切会漏掉一半：`_split_func_run()` 扫全文按最长名贪心切段，切完在「名后紧跟变量」处补 U+2009——源稿写 `\det A`，空格在转换时被吞，不补会粘成 detA；名后是括号则不补（`\det(A+B)` 是标准写法）。**两个算子名连着写**（`\ln\sec x`、`\ln\sec^2x`）走同一套：前者被并成一个已标正体的 `m:t='lnsec'`，后者把 `\sec` 包进 `m:sSup` 当底数——所以 `m:sty=p` 只在「切不出第二段」时才跳过，间隙判定也要看下一个兄弟的底数，否则排成 `lnsec x`，读起来像一个不存在的函数名。变量紧接函数名（`x\sec^2x`）仍不留缝，那是隐式乘法，不属本条 |
| `\left(-\frac{a}{b}\right)` 里出现空槽方框，排成 `( □ − a/b )` | latex2mathml 的 MathML 正常（fence + mo + mfrac），是 MML2OMML.XSL 把 `m:d` 内非定界符的 `mo` 当 `sepChr`，并按它把内容切成多个 `m:e`；负号紧跟左括号时第一段为空，Word 就画空槽。`add_math()` 的 `_fix_delims()` 把该字符做成 run 塞进相邻的 `m:e`、清空 `sepChr`、删掉空 `m:e`。分隔符两侧都非空（`\left(a-b\right)`，显示本来就对）不动。同一原因也让 `\left[\cdots\right]` 空槽（`⋯` 被当分隔符）——所以不要靠「括号里可别写负号」来躲，写法照常。`audit` 对本册扫「空 `m:e` + 非空 `sepChr`」，命中即 `[FAIL]` |
| `\boldsymbol{\omega}`、`\mathbf{\omega}` 不粗 | Word 对 `m:sty=b/bi` 的希腊字母不照办（实测仍是细的），拉丁字母才照办。`_bold_greek()` 换成数学粗体码位（α–ω → U+1D6C2–U+1D6DA），`polish_math()` 的 NFKC 还原**必须跳过这一段**，否则字符被还原成 ω 又把粗体丢了 |
| `$0\,^\circ\mathrm{C}$` 的度数圆圈印成两个点线小方框，前头空出一字宽（`13 °C` 中间空 9.7 pt） | latex2mathml 把紧贴 `^` 的细空 `\,`（`mspace`）当成上标底数，XSL 又把 `mspace` 丢掉，`m:sSup` 的底数就成了**空参数槽**；Word 对空槽画点线方框并按一个字宽占位。`add_math()` 末尾的 `_fix_empty_base()` 给空槽填一个零宽空格 run（U+200B）：`sSup`/`sSub`/`sSubSup`/`sPre` 的底数、`nary` 的 `e`/`sub`/`sup`。只补「结构上允许为空」的槽——`nary` 的 `subHide`/`supHide` 为 on 时跳过（`\sum_i` 本就不画），槽里嵌着 `m:d`/`m:f`/`m:m`/`m:rad` 的也跳过（那是内容丢失，补零宽字符等于抹掉证据）；`m:f`/`m:rad` 的空分子分母同理不补。作者照常写 `\,^\circ`。`audit` **尚未**加「上下标空槽」指标，这批只靠重建生效 |
| 树块里的 `│ ├ └ ─` 与中文/公式混排错位 | `_render_tree()`：剥掉行首树符，按「竖线数 + 分支符」算层级写 `w:ind`，一级节点加粗主色 |
| 文末空页（文档以表格结尾，Word 隐式补段推到下页） | `trim_trailing_empty()`：删多余空段，显式补一个 1pt 段落 |
| 空 run 缺字体（`m:sSub` 的空底数） | `polish_math()` 对空 run 也补字体，否则"缺字体 run = 0"指标被打破 |
| 生成的册子只能靠翻页找内容 | `index_anchors()` 预扫描标题与附录条目，标题写 `w:bookmarkStart` + `w:outlineLvl`（导航窗格、折叠三角）；首页「速达」、脉络行、小节下的「对应题目」由 `add_link` / `link_runs` 连到书签 |
| 跳过去就回不来（只能顺链走下去） | 反向由引擎补：脉络行挂 `_Tree{n}`、速达行挂 `_Nav`，每节「对应题目」行尾追加 `↑ 脉络` / `↑ 速达`；本节没上树时退到它名下第一个上树的 `h3` 那行 |
| 有题却没有「对应题目」行（高数/程序设计标签无节号） | 2.4.1 起正文题也进索引：正文 `:::quiz 【自拟】…` 与 `- **【自拟】** …` 按**所在节**挂靠（标签不必带节号）；附录题仍按 `§X.Y` 或「习题 X.Y 第 N 题」挂靠。`_is_task()` 白名单过滤掉 `【国内考法 · …】` 这类结构性标签 |

## 二、排版留白的三条经验

- **大 box（>半页）按主题拆成两个小 box**，否则整块 `cantSplit` 推到下页，前一页留 40% 空白
- **代码块超过约 14 行会被切成两截**（等宽 9pt、行距 1.0 时一页约 14 行）：注释合并到行尾、去掉空行与中间变量
- **速查卡前的附录页若只剩几行**（`page_break_before` 造成 85% 留白）：用**加题**补，不要删内容

## 三、python-docx 实现细节

- `pPr` / `tblPr` / `tcPr` 的子元素**有 schema 顺序**，直接 `append` 会写坏文件。用 `insert_element_before(el, *后续标签名)`
- 页眉不要用 tab 右对齐（会被 `Header` 样式的默认制表位干扰）。用 **1×2 无边框表格**，右格右对齐，表格 bottom border 当页眉线
- **页眉页脚字色用 `MUTED`（`5F6B78`），不要用 `GREY`（`8A94A0`）**：8.5pt 小字压白底，GREY 对比度只有 ~3:1，实打出来是「灰到看不清」（2.3.2 用户反馈）。GREY 只用于行内分隔符这类非阅读主体
- 容器块用单格表格 + `tcBorders` 左边框 + `w:shd` 底纹 + `w:cantSplit`（防框体被分页腰斩）
- 代码块必须给每个 run 补 `xml:space="preserve"`，否则连续空格被折叠，ASCII 树错位
- **超链接不能整段搬运 run**：`w:hyperlink` 只装 run，`m:oMath` 不在 run 层级。把整段 run 移到段尾的 hyperlink 里，`文字—公式—文字` 的顺序会被打乱。`link_runs()` 按「连续 run 组」分别包，同一段可以有多个 hyperlink，顺序保持不变
- **书签名以 `_` 开头等于 Word 隐藏书签**：`Document.Bookmarks.Count` 默认不数它们（COM 校验要先 `$d.Bookmarks.ShowHidden = $true`），功能不受影响；`w:hyperlink` 的 `w:anchor` 指向它照样能跳
- **链接可以先于书签出现**：`w:anchor` 由 Word 打开时解析，所以索引只需预扫描一遍标题/条目名，不必先渲染后置的附录。`index_anchors()` 就是为此存在——脉络块在前、附录书签在后，中间没有第二遍构建
- **大纲级别与折叠是两件事**：`w:outlineLvl` 只让导航窗格收得到；正文里的折叠三角只对内置 `Heading 1-9` 样式出现。所以 `h1/h2/h3` 既给 `pStyle=Heading N`（兼得折叠与将来的自动目录），又显式覆盖字号、字体、颜色、间距、缩进、底纹——样式只提供结构身份，视觉仍由自定义决定。只设 `outlineLvl` 的结果是「导航窗格有、正文没有折叠按钮」
- **插入段落会截断 keep-with-next 链**：标题的 `keep_with_next` 只牵到紧邻的下一个段落。在标题与正文之间插「对应题目」行之后，该行必须自己也设 `keep_with_next`，否则「标题 + 链接行」留在页底、正文翻到下一页，看起来就是孤悬标题（3 份实测中招）
- **脉络首行不能一律当章标题**：多数册子的树首行是概念式根名（「复合函数 z=f(u,v)…」），本该回顶部；但也有整棵树没有根行、首行直接写节名的情况（「五种表示法（2.5）」），那行必须连到那一节。判据取精确匹配与节号两档，都不成才回退章标题，**不做模糊匹配**——首行一旦参与模糊匹配就会连到某个 h3
- **括号里的数字默认不是节号**：`（物理页 112–117）` 的 112 是页码。只有 `\d+.\d+` 形态才当节号候选，否则页码会拿去匹配标题
- **回跳不能挂进标题段落**：`h2` 段落同时承载书签、`outlineLvl` 和导航窗格文字，多一个 run 就会让折叠标题写成「1.3 … ↑ 脉络」；`_next_hdr()` 又按标题原文对号，改了文本等于把后续定位全部搞乱。所以回跳挂在标题下已有的「对应题目」行尾，不另起段落——每节多一行约 14pt，二十节就是三成页
- **书签与超链接可以同段**：`bookmarkStart` 放在 `pPr` 之后、`hyperlink` 之外，`bookmarkEnd` 收段尾，Word 正常解析；`_Tree{n}` 盖住整行超链接、`_Nav` 盖住整条速达行，点过去都落在段落起点

## 四、LaTeX 转换的两个硬坑

1. **`\left| … \begin{bmatrix} … \end{bmatrix} … \right|` 必崩**：latex2mathml 抛 `ExtraLeftOrMissingRightError`，`add_math` 降级成红色 LaTeX 原文（`公式总数` 里不计失败，只能靠构建日志的 `!! 公式失败` 发现）。求行列式的绝对值时不要写成"竖线包住一个矩阵"，改成行列式单独成块、正文补一句"取绝对值"。
2. **行内公式以 `|` 开头且有 `\det`，`\det` 会被吞**：`$|\det A|$` 渲染成 "| dA|"；同样的 `\det` 放在 `$V=|\det A|$` 里却正常。定界符解析在公式开头时走了另一条分支。统一写 `$|A|$`。
3. 顺带确认：`\\[6pt]` 会漏成字面文本；`\begin{vmatrix}` 虽然引擎支持（定界符 `|`），但与已有各章的 `\det\begin{bmatrix}` 写法不一致，且竖线不会随行高拉伸，仍以 bmatrix 为准。
4. **`\dfrac` 与 `\frac` 等价**（都出 bar 型）；真正要小心的是**行内**堆叠分式会抬高行距——这是版式问题，不是转换问题，`lint_md` 只管结构块内的分式，正文里的靠视觉验收看。

## 五、改引擎后的影响面

**这是引擎级改动，不是内容级。** 改完 `scripts\` 下任一文件或新增容器类型后：

1. 所有已交付章节**必须全量重建**（`复习资料_重建.py --all`）；
2. 视觉验收从「关键页抽样」升级为**全量逐页看图**；
3. 重建前先备份，并确认没有并行会话正在构建。

只改路径、不改渲染逻辑的改动不受此限，但要用 A/B 对照证明产出逐字节相同：同一份 md、同一符号表、同一环境，改前脚本与改后脚本各建一次，比 `word/document.xml` 的 SHA-256。

**纯搬代码（拆模块、改函数归属）也走这条**：2.8.0 把单文件拆成四个模块时，就是拿 12 册覆盖各特性（图、矩阵、`cases`、积分、`flow`、`code` 树块、`quiz` 附录、℃、拓展册）各建一次，逐册比 SHA 全同才收的。只比一册不够——特性不同，走的分支也不同。

## 六、文件被 Word 占用时

`PermissionError: [Errno 13]` 的处理：

1. 先输出到源稿目录（引擎自动降级，退出码 3，**非 0**，不允许当作已交付）；
2. **不碰用户的 Word 实例**：不查 `Saved`、不代为 `Close`；把被占用的文件名报给用户，请他保存并关闭；

# 文字风格

> **什么时候读**：写对话回复、交付话术、自检报告、README / CHANGELOG 之前。写复习资料的叙述段（`:::note`、`:::box` 的过渡句）时同样适用；内容深度与配题规则以 `authoring.md` 为准，本文件只管怎么写。

## 一、四类文字，一套标准

| 场景 | 长度上限 |
|---|---|
| 对话回复 | 结论一段 + 不超过 3 个小节 |
| 交付话术 | 3 行 |
| 自检报告 | 表格优先，每项一行，不写过程 |
| 仓库文档 | 能省则省，不重复 `SKILL.md` 已有的命令 |

## 二、硬规则

1. **结论先行**。第一句是判断或结果，不是背景。删掉「这个问题需要先看一下」式铺垫。
2. **一句一件事**。单句不超过 40 字，超过就拆；一段不超过 4 句。
3. **不写元话语**。禁用「接下来我会」「综上所述」「值得一提的是」「不难发现」「简单说」。
4. **比喻须有净收益**。一个比喻省不掉三句以上说明就删掉。技术缺陷用中性动词：覆盖、回退、静默失败、未处理、忽略。
5. **口语词按表替换**（见第三节），句末语气词（吧 / 呢 / 啊 / 嘛）一律删。
6. **不加情绪**。不用感叹号；不用「非常」「极其」「严重」修饰程度。程度用事实表达：「102 个分式为压扁格式」，不写「分式问题很严重」。
7. **断言须有来源**。数字、版本、页码、「全量通过」必须能指回一次实测或一份文件；做不到就写「未验证」。
8. **不写第一人称叙事**。文档中写「实测」「校验结果」，不写「我试了」「我发现」。对话中可以用「我」陈述动作，但不用来表达倾向；给建议时显式标注「建议」。
9. **术语全文唯一**。同一对象始终同名：`渲染过程目录`、`成品`、`源稿`。不临时换成「工作台」「产物」「稿子」。
10. **格式克制**。一段最多一处加粗；标题用名词短语，不用问句、不用动词短语；文档不用 emoji。

## 三、口语词替换

| 不用 | 改用 |
|---|---|
| 说白了 / 一句话 / 其实 / 实际上 | 删 |
| 搞定 / 搞 / 弄 | 完成 / 生成 / 处理 |
| 踩坑 / 翻车 / 打架 | 已知问题 / 缺陷 / 冲突 |
| 兜底 | 回退 / 默认值 |
| 顺手 | 一并 |
| 别（表劝阻） | 不要 |
| 目前 / 现在 | 删，或写具体日期 |
| 建议你 | 建议 |

## 四、对照

反例：

> 这个仓库的结构一开始就有问题：它把一个外部目录当成自己的文件内容，而这个外部目录又正好是编辑现场。

改后：

> 该仓库的工作树依赖一个链接，链接目标即编辑目录，两者是同一份文件。

反例：

> 我这边没能导出预览图。Word COM 在这个终端里起不来，`ExportAsFixedFormat` 和 `SaveAs2` 都试过；按踩坑清单里的配方也仍然挂起。

改后：

> 预览图未导出。Word COM 在此终端不可用：`ExportAsFixedFormat` 与 `SaveAs2` 均阻塞，按 `_踩坑清单.md` 的配方重试仍挂起。

## 五、交付前自检

1. 首段能否独立说明结论。
2. 有无解释性铺垫或元话语。
3. 是否所有句子都在 40 字以内。
4. 比喻数是否超过 1 处。
5. 每个数字是否都能指回来源。

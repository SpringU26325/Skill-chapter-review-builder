# 单章复习资料构建器

## 运行环境与依赖

需要 **Windows + Microsoft Office**：页数统计与 PDF 导出走 Word COM，公式转换需要 Office 自带的 `MML2OMML.XSL`。不做其他平台适配，**WPS 不行**——它接管 `Word.Application` 后 COM 兼容层会静默失败，且不带 `MML2OMML.XSL`。

Python 依赖：`python-docx`、`latex2mathml`、`lxml`、`pymupdf`。优先用工作区的 `.venv`，缺失时 `scripts/_env.py` 会给出明确报错，不要在代码里写死解释器路径。

**工作区目录**（按名约定定位，脚本自动上溯找 `复习资料\`，不写绝对路径）：

| 路径 | 用途 |
|---|---|
| `Ebooks\` | 教材 PDF 主线，**只读** |
| `复习资料\_源稿\` | 各章 md、`<科目>_notation.md` |
| `复习资料\<科目>\` | 成品 docx，分科存放，不许散在根目录 |
| `复习资料\_render\` | 渲染过程文件，交付即清 |
| `复习资料\_locks\` | 并发锁，删了保护失效 |
| `复习资料\_台账.md` | **唯一进度真相**：页码、分册、成品页数、下一章、待办 |
| `复习资料\_踩坑清单.md` | 踩坑事实，改引擎、写公式、调 COM 前必读 |

**本 skill 只管「复习资料」这一类交付物。** 一般性的 Word 排版、美化、改写任意 docx，走通用文档 skill，不要走这里——版式体系完全不同（这里是七容器私有方言 + 自建引擎）。

## 接手三步（任何会话进来先做）

1. **读台账**：`复习资料\_台账.md`——已完成章节、页码对照、分册划分、下一章。读不到就扫 `复习资料\<科目>\` 下的 docx 反推现状，**降级继续，不要中断**。教材原书在 `Ebooks\`，节号、公式号、习题难度都以那里为准。
2. **读追加要求（可选）**：工作区若有 `AGENTS.md`，只读其「额外要求」一节——那是用户当轮的临时加码，优先级高于本 skill 默认。**本 skill 不依赖这个文件**：常规要求（一次一章、来源标注与禁冒充、课堂扩展在出题范围内、跨册不写编号、拓展册独立成册、进度只写台账）已内化在 `references/` 里；文件不存在或被整份删掉，按默认照常执行，**不要因此中断或反问**。任何情况下都**不写**它——进度只写 `复习资料\_台账.md`。
3. **确认范围**：这次做哪一章、拆几册、是新课还是返工。用户没说清就问，不要自行假设章节边界。

## 硬约束

1. **一次只处理一章**，一章可以交多册（上/中/下/拓展）。用户一次发多章时回复：「请一次只发一章，我们从第一章开始。」
2. 交付物一律叫**「复习资料」**，不叫讲义、不叫笔记、不叫提纲。用户口语说「帮我做个提纲」时，照做，只是成品文件名与内部标题仍是「复习资料」——不要真的写成提纲。
3. **每个知识点配一道题**，不留裸知识点。
4. **禁止悬空引用**：引用的公式号、章节号、定理名必须在本册或已交付册里真实存在。
5. 公式以**渲染后重建**为准；PDF 的文字层与 OCR 结果都可能是错的，不能直接采信。宿主自带的 PDF 工具（读文本、切图、取页码）只用来**定位与索引**——查页码、节号、例题编号可以，**照抄文字层的公式不行**，必须回到教材原书核对并重建。

## 命令速查

在**复习资料工作区根目录**执行（脚本按 cwd 上溯定位工作区，换目录也不用改代码）。

**下文命令里的 `<skill>` 一律指「本 SKILL.md 所在目录」**——不同宿主把它挂在不同位置（`<工作区>\.agents\skills\chapter-review-builder\`、`~/.codex/skills/…`、其他宿主的 skills 根），不要照抄某个具体路径，也不要把它当成工作区里的目录。搞不清时先 `pwd`/列出本文件路径再拼。

```bash
# 构建（增量）：只重建 md 比 docx 新的
python "<skill>\scripts\复习资料_重建.py"

# 预演：只打印待重建清单，不写文件、不加锁
python "<skill>\scripts\复习资料_重建.py" --dry

# 全量重建（改过引擎后才用这个，会让所有已交付成品重写一遍）
python "<skill>\scripts\复习资料_重建.py" --all

# 单科目 + 附页数统计
python "<skill>\scripts\复习资料_重建.py" 高等数学 --all --pdf

# 交付前审计：四项硬指标 + 公式预检
python "<skill>\scripts\复习资料_audit.py" <md> <docx>

# md 级前置检查（写 md 之后、构建之前，先跑这个能省一轮返工）
python "<skill>\scripts\复习资料_lint_md.py" <md> [md2 ...]

# 页数 + 空页筛查（只读 COM，绝不导出）
python "<skill>\scripts\复习资料_页检.py" <docx> [docx2 ...]

# 视觉验收：准备 → 渲染 → 清理
python "<skill>\scripts\复习资料_渲染.py" --prepare <docx>
python "<skill>\scripts\复习资料_渲染.py" --render --dpi 140
python "<skill>\scripts\复习资料_渲染.py" --clean
```

**线性代数额外一步**（通用审计不含记号规则，必须单独跑）：

```bash
python "<skill>\scripts\lint\线性代数_lint.py" 线性代数_第1章.md 线性代数_第2章上.md
```

退出码 0 = 全过；1 = 有 ERROR，不许交付。WARN 不阻断，但要在自检报告里逐条说明。

`渲染 --prepare` 之后，**Word COM 那一段必须由 PowerShell 工具执行包内的 `render.ps1`**，且**必须后台执行**（`run_in_background`）再轮询 `.renderlog.txt`——前台调用拉起 GUI 后工具可能提前返回，留下孤儿 Word，两个实例抢同一份 docx 就会弹「文件正在使用」模态框，之后所有 COM 调用（含 `Quit`）都返回 `RPC_E_CALL_REJECTED`，看起来像「导出挂死」。正常一份 8 页资料 8–10 秒出 PDF。

`render.ps1` 自带熔断：日志 180 秒没有新增就记 `TIMEOUT|`、强杀 Word 让阻塞的 COM 立刻抛错，然后收尾退出（阈值可用 `CRB_RENDER_TIMEOUT` 临时调整）。**判读只看日志**——超时同样打印 `FAIL|…远程过程调用失败`，退出码与「只挂了一个文件」没有区别，`TIMEOUT|` 才是挂死的证据。脚本退出前会把本次新起却没退干净的 WINWORD 强杀（日志 `CLEANED leftover`），只杀自己拉起的实例，不动用户开着的窗口。

前提检查：执行前 `WINWORD` 进程数必须为 0、过程目录内无 `~$` 锁文件；有就先让用户点掉模态框，再优雅 `Close(0)` → `Quit()`，不要连刷。中文路径**可以**导出（已实测），不要把挂死归因于路径。

`render.ps1` 里的一个硬约束：**清单必须在 `New-Object -ComObject Word.Application` 之前读取并转成 `[string]`**。改到实例创建之后再读，`ExportAsFixedFormat` 会永久阻塞且不报错。

## 移植

1. 整个目录复制到任意宿主的 skills 目录即生效，**包内没有任何宿主目录名、没有机器绝对路径，也没有 `.git`**——版本库放在包外，复制时不会把历史带过去。
2. 换机器只需装好上面四个 Python 依赖；解释器位置由工作区 `.venv` 或环境自行提供。
3. `MML2OMML.XSL` 按三级探测：环境变量 `MML2OMML_XSL` → 包内 `assets\MML2OMML.XSL` → Office 安装路径。三级都找不到时报错并提示定位方式，不会静默失败。

# 交付、并发与 COM 纪律（Step 3 读这一份）

> **什么时候读**：docx 构建完成、要交付或要动 Word 的时候。

## 一、存放与命名

- **分科存放（强制）**：`复习资料\<科目>\`，本科文件一律放本科文件夹内，**禁止散落在根目录**。发现历史文件散落时主动迁移。
- 文件名严格为：`[科目名称]_第X章[上|下|中|拓展]_复习资料.docx`（方括号后缀可省）。
- 源稿放 `复习资料\_源稿\`，命名 `<科目>_第X章.md`（**必须带科目前缀**）。不要用 `math`、`ch1`、`gs6a` 这类泛名——多科目并行会互相覆盖。

**文件名即接口**：`<科目>_第X章.md` → `复习资料\<科目>\<同名>_复习资料.docx`。页眉写在 md 的 `@header`，符号表 `<科目>_notation.md` 存在就自动注入。没有清单文件、没有每章脚本。

## 二、交付话术

- 单册：**「XX第X章已完成并导出到 复习资料\XX\XX_第X章_复习资料.docx，自检报告无异常，请查收。」**
- **一章多册时列出全部文件名**（如「上 / 下 / 拓展 共 3 份，各 8–12 页」），不要只报第一册。
- **不要用文件预览面板打开 docx**：本机预览字号太小、不可读，且预览进程会锁住 docx 导致构建失败。交付时只给路径。

## 三、收尾清理

`复习资料\` 是成果仓库，`_render\` / `_迁移\` 是工作台，交付即清。

**可直接删**：渲染图 `*.png`、带版本后缀的过程 PDF（`v2…v9`、`fix1…fix7`、`preview*`）、引用的路径已不存在的脚本、一次性探测脚本（`t*.py`、`probe*.py`、`test_*.py`）、0 字节文件、空目录、构建中间 docx。

**必须保留**：`复习资料\_源稿\` 下的各章 `.md`、`<科目>_notation.md`、`复习资料\_locks\`（删了并发保护失效）、`复习资料\` 下的成品。

**删除前**：`grep -l <文件名> scripts\*.py` 确认无引用；只删过程目录，**不碰** `复习资料\<科目>\` 成品、`Ebooks\`、工作区台账。

**原因**：同一份稿子会迭代出十几版，攒到几百个文件后「哪个是最终版」不可判断，`grep`/`glob` 的结果被历史文件淹没。清理的价值是**让目录本身说明当前进度**。

## 四、多科目 / 多会话并发

**可以同时开工**，三条前提：

1. **文件带科目前缀**——重建脚本靠前缀认科目。
2. **只改自己的文件**；工作区台账（`复习资料\_台账.md`）是共享的，改前先读最新版，**只追加本章事实、不整段重写**，别两个会话同时编辑。`AGENTS.md`（若存在）、`Ebooks\` **只读**。
3. **构建统一走重建脚本**——按科目分锁（`_locks\.build_<科目>.lock`），不同科目同时构建互不等待，同科目才排队；默认增量，各科只重建自己改过的章节。

**唯一串行的是 Word COM 转 PDF**（`_locks\.pdf.lock`，跨科目排队）：Word 是单实例资源，同时转会互相关掉文档。`--pdf` 已包在锁内，手工转时先确认另一个会话没在转。

> 迁移或换机时注意：锁目录变了，新旧锁互不互斥。迁移窗口内禁止任何构建。

## 五、Word COM 使用纪律（防「文档恢复」残留）

**转 PDF 一律走重建脚本的 `--pdf`**（默认增量，只重建 md 比 docx 新的章节；`--all` 仅在改过构建引擎后使用，否则会把所有已交付成品重建一遍）。不要为每轮微调反复 `New-Object -ComObject Word.Application`。确需自定义导出（dpi/clip 裁切、单独出一份校验 PDF）时，**复用同一个实例**，别一轮一启停。

手工调用 COM 必须成套做完：

1. 优先 `GetActiveObject("Word.Application")` 复用实例；`Visible=$false`、`DisplayAlerts=0`、`Documents.Open(..., ReadOnly=$true)`。
2. 收尾顺序固定：`$d.Close(0)` → `$w.Quit()` → `ReleaseComObject($d)` → `ReleaseComObject($w)` → `[GC]::Collect()`。**只 release `$w` 会留下僵尸 WINWORD 进程**，之后构建写 docx 会静默失败（时间戳不更新）。
3. **默认禁止 `Stop-Process -Force` / `taskkill` 结束 WINWORD**。强杀或异常退出会让 Word 来不及清掉 `%APPDATA%\Microsoft\Word\*.asd` 自动恢复副本，并在 `HKCU\...\Word\Resiliency` 留下恢复项；用户下次开关 Word 就会弹出「文档恢复」任务窗格。恢复列表里是**过程版副本**，误点会把已交付的最终版覆盖回去。
   **仅两处例外，且都已写进 `render.ps1`，不要在别处模仿**：① 日志 180 秒不动（看门狗判挂死）；② 脚本自身 `Quit()` 后 15 秒仍有本次拉起的实例（`$base` 之外的 PID，留着会撞下一次导出）。两处都只杀本次新起的实例、不碰用户自己开的 Word，日志里分别留 `TIMEOUT|` 与 `leftover PID:`。强杀后若弹「文档恢复」，按第 5 条让用户选「否」。
4. 遇 `~$xxx.docx` 锁文件：先 `GetActiveObject` 查 `Saved`，`Saved=True` 才允许 `Close(0)`；`Saved=False` 停下交给用户。确属自己起的隐藏实例用 `$w.Quit()` 优雅退出，仍不退就报告用户，不强杀。
5. **交付前只读确认**：`Get-Process WINWORD` 无自己起的残留、`复习资料\<科目>\` 无 `~$` 锁文件。若 Word 已弹出「文档恢复」询问，指导用户选 **「否，删除这些文件。我已保存了需要的文件」**——成品已落盘且四项硬指标通过，恢复副本是旧版；**不要手动去 AppData 删文件**，交给 Word 自己清。
6. **预览进程可直接强杀**：预览面板会拉起文档预览引擎并**锁住 docx**，后果是构建脚本打印「正式文件被占用」并把结果写到源稿目录（**退出码 3，非 0**）。遇到预览进程占锁直接结束它（用户已授权）。查真实持有者用 `scripts\_wholock.py <docx>`（Restart Manager，直接打印 pid 与进程名），**不要靠猜**。`WINWORD` 仍按第 3 条禁止强杀。
7. **COM 只读检查统一走页检脚本，不要手写 PowerShell COM**：页数、逐页字符数、空页筛查全在脚本里；它优先复用已开的 Word 实例、只关自己的文档、带全局锁。手工 COM 仍是例外通道，用完必须成套收尾。
8. **导出看图的前提**（纠正「通道整体不可用」的旧误判）：`ExportAsFixedFormat` / `SaveAs2(…,17)` 本身可用，前提是三条同时满足——
   - ① **由 PowerShell 工具直接执行**。同样命令包进 `python subprocess → powershell -NonInteractive` 必挂（90–240s 超时）。这是过去误判的真正原因，不是 docx 内容、打包方式或样式的问题。
   - ② **`Visible=$true` + `Documents.Open(..., ReadOnly=$false)`**。`ReadOnly=$true` 或隐藏实例会让导出死循环；而同实例的 `ComputeStatistics(2)`、`Range.Text` 正常，所以页检能过、导出却挂。
   - ③ **路径必须经 UTF-8 清单文件传入**，不要写进 `.ps1` 字面量、也不要放进命令行参数：PowerShell 5.1 无 BOM 时按 ANSI 解码，中文字面量会乱码。**中文路径本身不影响导出**（11-11 实测：源与目标都含中文，8 页 10.3s 成功），历史上「中文路径挂死」的结论是把清单读取时序的缺陷误归因到路径上。

   入口：`scripts\复习资料_渲染.py --prepare <docx...>` 生成副本与清单，并把 `render.ps1` 复制进同一目录 → PowerShell 工具执行它（**打印出来的绝对路径可直接粘贴**）→ `--render` 输出逐页字数与 PNG。

   症状：出现 `~$xxx.docx` 锁文件且无 PDF 产出 = 挂在导出。先 `GetActiveObject` → `Quit()` 优雅退出再重试，**不要连刷**——每次超时留一个卡死实例，后续调用会连到坏实例，造成「越试越挂」的假象。

9. **导出结果只认日志，不认退出码**。`render.ps1` 自带看门狗：日志 180 秒没新增就写 `TIMEOUT|`、强杀 Word 让阻塞的 COM 立即抛错，脚本随后打印 `FAIL|…|远程过程调用失败` 并以 0 退出——与「只挂了一个文件」长得一样。**`TIMEOUT|` 才是挂死的证据**，出现即判本次导出失败、PDF 不完整。正常 8 页资料 6–10 秒出 PDF；自测可用 `CRB_RENDER_TIMEOUT=3` 把阈值压到 3 秒验证熔断路径。
10. **不要往 `render.ps1` 的 `try/finally` 之后追加逻辑**。COM 抛错后 finally 之后的语句不会执行（11-11 连测两次：日志与 stdout 都收不到），收尾、判定、统计一律写在 finally 内。

## 六、新科目接入（3 步，不改引擎）

1. 写 `复习资料\_源稿\<科目>_第1章.md`，头部三行：`# 第1章 …` / `@sub …` / `@header <科目> · 第1章 …`
2. （可选）建 `复习资料\_源稿\<科目>_notation.md`，内含 `<!-- inject:compact -->…<!-- /inject:compact -->` 段
3. （可选）复制 `scripts\lint\线性代数_lint.py` 为 `<科目>_lint.py` 改规则

成品自动出现在 `复习资料\<科目>\`，配色、容器、公式处理全部继承。

**别为了「看起来完整」去建用不上的符号表或检查器。** 只有当真存在「一眼看不出错、但读者会误解」的记号约定时（像线代的圆括号=列向量），才值得再写一份 `<科目>_lint.py`。

## 七、交付后同步台账（只写一处）

每章交付后**只更新 `复习资料\_台账.md`** 一处：页码对照、分册数、成品页数、下一章。

**`AGENTS.md` 不写。** 它是工作区的指令文件，是会话的输入而不是本 skill 的产物；常规要求已全部内化在本 skill 里，删掉它不影响执行。它顶部那两行「已完成 / 下一章」与本台账重复，两份必然漂移，**以台账为准**。

需要动它时，只在交付回复里给一行建议文本，由用户自己决定落不落：

> 如需同步 `AGENTS.md` 顶部进度，建议改为：「已完成 <N> 份 ……；下一章 ……」（数字取自台账，不要凭记忆填）。
